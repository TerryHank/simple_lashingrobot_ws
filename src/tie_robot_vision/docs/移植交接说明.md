## 工作区确认和保存

当前扫描方案一定要先确认工作区。工作区不是 ROS workspace，而是相机图像中的钢筋作业四边形，保存路径为：

```text
$TARGET_WS/src/tie_robot_vision/data/manual_workspace_quad.json
```

该文件至少包含 4 个图像像素角点；在相机世界坐标和 TF 可用时，还会保存 `corner_world_camera_frame` 和 `corner_world_map_frame`。扫描分支 `MODE_SCAN_ONLY=3` 会读取这个文件做透视展开和全局工作区过滤；没有工作区时，服务会拒绝全场扫描，并提示先确认工作区域。

推荐保存流程：

1. 启动相机、世界坐标处理和 pointAI。
2. 确认 `/Scepter/worldCoord/raw_world_coord` 有数据。
3. 从前端 IR 图上选择 4 个工作区角点，发布到 `/web/pointAI/set_workspace_quad`。
4. pointAI 在回调中读取当前 raw world 坐标，写入 `manual_workspace_quad.json`，并发布 `/pointAI/manual_workspace_quad_pixels`。
5. 重新触发扫描视觉。

没有前端时，也可以由适配 agent 写一个很小的 ROS 节点，向 `/web/pointAI/set_workspace_quad` 发布 `std_msgs/Float32MultiArray`，数据按 `x1,y1,x2,y2,x3,y3,x4,y4` 排列。不要在没有相机 raw world 数据的情况下盲目手写世界角点；这样后续扫描账本和执行微调的全局过滤会失真。

确认保存结果：

```bash
test -f "$TARGET_WS/src/tie_robot_vision/data/manual_workspace_quad.json"
rostopic echo -n1 /pointAI/manual_workspace_quad_pixels
```

## 扫描账本如何生成

`tie_robot_vision` 只负责识别绑扎点并通过服务、话题返回点；它不负责写整机扫描账本。当前新工程里的账本由 `tie_robot_process` 消费视觉结果后生成，核心文件是：

```text
/home/hyq-/simple_lashingrobot_ws/src/tie_robot_process/data/pseudo_slam_points.json
/home/hyq-/simple_lashingrobot_ws/src/tie_robot_process/data/pseudo_slam_bind_path.json
/home/hyq-/simple_lashingrobot_ws/src/tie_robot_process/data/bind_execution_memory.json
```

当前工程完整流程是：

```text
/cabin/start_pseudo_slam_scan
-> tie_robot_process::run_pseudo_slam_scan
-> 调用 /pointAI/process_image，request_mode=3
-> 获得 PointCoordinatesArray
-> 写 pseudo_slam_points.json
-> 规划并写 pseudo_slam_bind_path.json
-> 重置 bind_execution_memory.json
```

因此，把这个 zip 移植到旧工作区后，如果目标工程没有 `tie_robot_process` 这层流程编排，就不会自动生成上述 3 个账本文件。下一个工程师或 agent 需要二选一：

1. 只保留视觉能力：调用 `/tie_robot_vision/process_image`，显式传 `request_mode=3`，直接使用服务响应里的 `PointCoordinatesArray`。
2. 需要整机账本：在目标工程的流程层新增消费者，按自己的工程路径写 `pseudo_slam_points.json`、`pseudo_slam_bind_path.json` 和执行记忆文件；或者继续移植 / 适配当前工程的 `tie_robot_process` 账本逻辑。

如果走旧兼容服务要特别注意：旧 `fast_image_solve/ProcessImage` 请求没有 `request_mode` 字段，`legacy_fast_image_solve_bridge.py` 默认把旧请求转成 `MODE_EXECUTION_REFINE=4`，适合旧单点绑扎微调。如果要让旧兼容入口执行扫描，启动时必须指定：

```bash
roslaunch tie_robot_vision legacy_20260403_vision.launch backend_request_mode:=3
```

这只解决「旧服务调用转成扫描识别」的问题，不等于自动写账本；账本仍然要由目标工程流程层保存。

## 执行层微调如何使用

执行层微调使用 `MODE_EXECUTION_REFINE=4`。当前链路用于「索驱或末端已经到达某个区域附近，再用当前相机帧细调实际可绑点」。

输入前提：

1. `/Scepter/worldCoord/raw_world_coord` 和 `/Scepter/worldCoord/world_coord` 正常。
2. `Scepter_depth_frame -> gripper_frame` TF 正常；控制层必须用这个 TF 把视觉点转到末端坐标。
3. 有手动工作区时，执行微调会先排除全局工作区外的点。
4. `/tie_robot_vision/moduan_gesture_data` 可选；有它时，结果图和 TCP ROI 能按当前线性模组位置显示得更准确。

调用方式：

```text
/tie_robot_vision/process_image
  tie_robot_vision/ProcessImage.request_mode = 4

或旧兼容入口：
/pointAI/process_image
/Moduan/process_image
  fast_image_solve/ProcessImage，无请求字段，由 bridge 默认转成 request_mode=4
```

输出语义：

1. 服务响应和 `/coordinate_point` 输出的是 `Scepter_depth_frame` 下的相机原始坐标点。
2. `/perception/lashing/points_camera` 同样保持相机原始坐标语义。
3. 控制层下发线性模组前，必须把点从 `Scepter_depth_frame` 转到 `gripper_frame`，再按目标工程自己的执行坐标口径下发。
4. 当前微调算法先用 TCP 执行盒作为 Hough 二值图 ROI，再按手动工作区全局多边形过滤候选点，剩余点按 TCP 蛇形顺序作为一组输出；返回 1、2、3、4 个点都属于有效结果，返回 0 个点则由执行流程决定跳过、重试或报警。

当前新工程中，单点绑扎 `/moduan/sg` 和路径规划 + 微调模式都会调用 `request_mode=4`，然后把相机点转换到 `gripper_frame`。移植到其它工作区时，不要把相机原始坐标直接当末端坐标使用。

## 旧工作区兼容关系

旧 `20260403` 工程中，`chassis_ctrl` 已写死使用：

```text
fast_image_solve/ProcessImage -> /pointAI/process_image
fast_image_solve/ProcessImage -> /Moduan/process_image
```

旧 `fast_image_solve/ProcessImage.srv` 没有请求字段，响应只有：

```srv
---
int32 count
PointCoords[] PointCoordinatesArray
```

新版 `tie_robot_vision/ProcessImage.srv` 增加了 `request_mode`、`success`、`message` 和高度诊断字段。两个服务类型的 MD5 不一致，不能直接把新版 pointAI 挂到 `/pointAI/process_image` 给旧 `chassis_ctrl` 调用。

因此旧适配 launch 的服务关系是：

```text
pointAI 新版内部服务：
/tie_robot_vision/process_image
  类型：tie_robot_vision/ProcessImage

旧兼容桥对外服务：
/pointAI/process_image
/Moduan/process_image
  类型：fast_image_solve/ProcessImage
```

桥接节点默认把旧无请求字段调用转成：

```text
tie_robot_vision/ProcessImage.request_mode = 4
```

也就是执行微调 `MODE_EXECUTION_REFINE`。如果旧展示链路需要全场扫描，可用：

```bash
roslaunch tie_robot_vision legacy_20260403_vision.launch backend_request_mode:=3
```

## 旧状态桥接

旧 `chassis_ctrl/cabin_upload` 与 `tie_robot_vision/cabin_upload` 字段一致，包名不同；旧 `chassis_ctrl/linear_module_upload` 比当前视觉消息少 `light_state` 字段。为了避免 ROS 话题 MD5 不匹配，`legacy_20260403_vision.launch` 会启动两个状态 relay：

```text
/cabin/cabin_data_upload
  chassis_ctrl/cabin_upload
-> /tie_robot_vision/cabin_data_upload
  tie_robot_vision/cabin_upload

/moduan/moduan_gesture_data
  chassis_ctrl/linear_module_upload
-> /tie_robot_vision/moduan_gesture_data
  tie_robot_vision/linear_module_upload
```

随后 `robot_tf_broadcaster` 订阅 `/tie_robot_vision/cabin_data_upload`，pointAI 订阅 `/tie_robot_vision/moduan_gesture_data`。

## 故障排查

如果 `roslaunch` 报 `legacy_fast_image_solve_bridge requires the old fast_image_solve package`，说明当前环境没有 source 旧工作区，或旧工作区缺少 `fast_image_solve`。先运行：

```bash
source /home/hyq-/simple_lashingrobot_show/simple_lashingrobot_ws20260403/simple_lashingrobot_ws/devel/setup.bash
```

如果旧 `chassis_ctrl` 调 `/pointAI/process_image` 报服务类型不匹配，检查是否误把 `vision_stack.launch` 当旧工作区入口使用。旧展示工作区必须启动：

```bash
roslaunch tie_robot_vision legacy_20260403_vision.launch
```

如果 pointAI 一直等待图像，检查：

```bash
rostopic hz /Scepter/depth/image_raw
rostopic hz /Scepter/ir/image_raw
rostopic hz /Scepter/worldCoord/raw_world_coord
rostopic hz /Scepter/worldCoord/world_coord
```

如果执行微调没有点，检查 `/perception/lashing/execution_refine_base_image`，图中 `H` 表示 Hough 原始交点，`ZERO` 表示没有有效 3D 坐标，`OUT` 表示超出 TCP 执行范围，`SEL` 表示最终输出。

如果 TF 不动，检查旧状态 relay：

```bash
rostopic hz /tie_robot_vision/cabin_data_upload
rostopic hz /tie_robot_vision/moduan_gesture_data
rosrun tf tf_echo map Scepter_depth_frame
rosrun tf tf_echo Scepter_depth_frame gripper_frame
```

如果相机节点找不到 Scepter 动态库，确认 `dependencies/Lib/libScepter_api.so` 存在，并通过 `scepter_camera.launch` 中的 `LD_LIBRARY_PATH` 注入。
